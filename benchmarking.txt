## ✅ 1. Fixed `main.py` (with transcriptions saved + bug fixes)

```python
import os
import time
import csv
import librosa
import whisper
import torch
from dotenv import load_dotenv
from transformers import AutoProcessor, VoxtralForConditionalGeneration
from huggingface_hub import login

# Load environment variables
load_dotenv()

# Authenticate with Hugging Face
hf_token = os.environ.get("HF_TOKEN")
if not hf_token:
    raise ValueError("HF_TOKEN environment variable not set. Please provide your Hugging Face token.")

login(hf_token)

# Paths
AUDIO_FOLDER = "audio"
OUTPUT_CSV = "benchmark.csv"

# Load models
print("Loading Whisper Large...")
whisper_model = whisper.load_model("large")

print("Loading Voxtral Mini...")
device = "cuda" if torch.cuda.is_available() else "cpu"
processor = AutoProcessor.from_pretrained("mistralai/Voxtral-Mini-3B-2507")
voxtral_model = VoxtralForConditionalGeneration.from_pretrained(
    "mistralai/Voxtral-Mini-3B-2507",
    torch_dtype=torch.bfloat16 if device == "cuda" else torch.float32
).to(device)

# Transcription functions
def transcribe_whisper(audio_path):
    start = time.time()
    result = whisper_model.transcribe(audio_path)
    end = time.time()
    duration = librosa.get_duration(path=audio_path)
    rtf = (end - start) / duration
    return result["text"], rtf

def transcribe_voxtral(audio_path, language="en"):
    start = time.time()
    # Load audio
    audio, sr = librosa.load(audio_path, sr=processor.feature_extractor.sampling_rate)
    inputs = processor(
        audio=audio,
        sampling_rate=sr,
        return_tensors="pt",
        padding=True
    ).to(device, dtype=torch.bfloat16 if device == "cuda" else torch.float32)

    with torch.no_grad():
        outputs = voxtral_model.generate(
            **inputs,
            max_new_tokens=1024,
            language=language  # Voxtral supports language hint
        )
    text = processor.batch_decode(
        outputs[:, inputs.input_ids.shape[1]:],
        skip_special_tokens=True
    )[0].strip()
    end = time.time()
    duration = librosa.get_duration(path=audio_path)
    rtf = (end - start) / duration
    return text, rtf

# Auto-detect language (optional improvement)
# For now, assume English. You can extend this with language detection if needed.

# Benchmarking
results = []
for file in os.listdir(AUDIO_FOLDER):
    if file.endswith((".wav", ".mp3")):
        path = os.path.join(AUDIO_FOLDER, file)
        print(f"Processing: {file}")

        # Whisper
        try:
            whisper_text, whisper_rtf = transcribe_whisper(path)
        except Exception as e:
            whisper_text, whisper_rtf = f"ERROR: {str(e)}", -1

        # Voxtral (default to English; you can improve this)
        try:
            voxtral_text, voxtral_rtf = transcribe_voxtral(path, language="en")
        except Exception as e:
            voxtral_text, voxtral_rtf = f"ERROR: {str(e)}", -1

        results.append([
            file,
            whisper_text,
            whisper_rtf,
            voxtral_text,
            voxtral_rtf
        ])

# Save CSV
with open(OUTPUT_CSV, "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow([
        "Audio File",
        "Whisper Transcription",
        "Whisper RTF",
        "Voxtral Transcription",
        "Voxtral RTF"
    ])
    writer.writerows(results)

print(f"Benchmark complete! Results saved to {OUTPUT_CSV}")
```

> - Corrected `librosa.get_duration(path=...)`
> - Added proper audio loading for Voxtral using `librosa.load` at correct sampling rate
> - Added error handling

> distribution=$(. /etc/os-release;echo $ID$VERSION_ID)

Great question! **CUDA itself doesn’t have “commands” you run directly like `docker` or `python`**, but when working with **GPU-accelerated deep learning (like Whisper or Voxtral)** on a server, you **do need to verify and monitor CUDA/GPU usage** using a few essential **NVIDIA/CUDA-related commands**.

You **don’t run CUDA commands to execute your model**, but you **use them to check if your setup is working correctly** — especially since you’re using Docker + GPU.

---

### ✅ Essential CUDA / GPU Commands You Should Know & Run

#### 1. **Check if NVIDIA drivers & GPU are visible**
```bash
nvidia-smi
```
- **What it does**: Shows GPU name, driver version, CUDA version, memory usage, and running processes.
- **When to run**:
  - Before starting your container → to confirm GPU is detected.
  - While your script is running → to see if GPU memory is being used.
- **Expected output**: A table with your GPU (e.g., A100, V100, RTX 4090) and ~0% utilization before run, then high usage during inference.

> 🔴 If this command fails → **NVIDIA drivers not installed** → your GPU won’t work!

---

#### 2. **Check CUDA version (on host)**
```bash
nvcc --version
# OR
cat /usr/local/cuda/version.txt
```
- **Note**: The CUDA version shown here is the **host CUDA toolkit version**.
- **Important**: Your **Docker image** (e.g., `pytorch/pytorch:2.3.0-cuda12.1...`) already includes its own CUDA runtime — so you don’t need to match host CUDA exactly, as long as the **driver is new enough**.

> ✅ Rule of thumb: **NVIDIA driver ≥ required by Docker image’s CUDA version**  
> (e.g., CUDA 12.1 needs driver ≥ 530.xx)

---

#### 3. **Verify GPU access inside Docker container**
After you `docker-compose exec dev bash`, run:
```bash
nvidia-smi
```
- If it works → your container has GPU access ✅  
- If it fails → your `compose.yaml` or NVIDIA Docker setup is broken ❌

> 💡 This is the **most important test** — if `nvidia-smi` works inside the container, PyTorch will see the GPU.

---

#### 4. **Check if PyTorch sees the GPU (inside Python)**
Inside your container, run:
```python
python3 -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```
- Should output:
  ```
  True
  Tesla V100-SXM2-32GB   # (or your GPU name)
  ```

> 🔍 If this says `False`, your model will run on CPU → **very slow!**

---

#### 5. **Monitor GPU while your script runs**
In a **separate terminal** (while `python main.py` is running):
```bash
watch -n 1 nvidia-smi
```
- Shows real-time GPU utilization, memory usage, and power.
- You should see:
  - **GPU-Util**: 30–90%
  - **Memory-Usage**: Several GB used (Whisper-large ~5–10 GB, Voxtral ~6–8 GB)

> 🚨 If memory usage is 0 → your code is running on CPU by mistake!

---

### ❌ Common Mistakes (and how to fix)

| Symptom | Likely Cause | Fix |
|-------|--------------|-----|
| `nvidia-smi` not found in container | Missing `runtime: nvidia` in `compose.yaml` | Add `runtime: nvidia` |
| `torch.cuda.is_available()` = False | Wrong Docker image (no CUDA) | Use `pytorch/pytorch:...-cuda...` image |
| OOM (Out of Memory) | Too many models or large batch | Run one model at a time; add `torch.cuda.empty_cache()` |
| Slow inference | Accidentally using CPU | Check `device = "cuda"` and `nvidia-smi` during run |

---

### ✅ Summary: What You Should Run

| When | Command | Purpose |
|------|--------|--------|
| **Before anything** | `nvidia-smi` | Confirm GPU is visible on host |
| **After `docker-compose up`** | `docker-compose exec dev nvidia-smi` | Confirm GPU in container |
| **Inside container** | `python3 -c "import torch; print(torch.cuda.is_available())"` | Confirm PyTorch sees GPU |
| **While running `main.py`** | `watch -n 1 nvidia-smi` (in another terminal) | Monitor GPU usage |
| **After crash** | Check logs + `nvidia-smi` | Diagnose OOM or driver issues |

---

You **don’t need to run "CUDA commands" to execute your model** — your Python code (with `torch`) uses CUDA automatically **if the environment is set up right**.

But **you absolutely must verify** the above steps — otherwise, you might think you’re using the GPU, but you’re actually running on CPU (which is 10–50x slower)!
